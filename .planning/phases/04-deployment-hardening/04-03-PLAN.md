<task type="auto">
  <name>Task 1: Create backup.mjs script for pg_dump with gzip compression</name>
  <files>scripts/backup.mjs</files>
  <action>
    Create `scripts/backup.mjs` — a standalone Node.js script that wraps pg_dump:

    Features:
    - Reads DATABASE_URL from environment (same variable as app uses)
    - Parses DATABASE_URL to extract host, port, dbname, user for pg_dump arguments
    - Runs `pg_dump` via child_process.execFileSync with:
      - `--no-owner` (portable, no role mismatch on restore)
      - `--clean` (drops existing objects before restore, making restore idempotent)
      - `--if-exists` (suppresses errors when dropping non-existent objects)
      - `--no-privileges` (avoids permission errors on restore)
      - `--format=custom` (compressed, parallel restore capable)
      - `--compress=9` (max gzip compression)
    - Output file: `{BACKUP_DIR}/bcm-{YYYY-MM-DD-HHmmss}.dump`
    - BACKUP_DIR defaults to `/backups` (mounted volume in docker-compose)
    - Logs to stdout with [backup] prefix
    - Returns exit code 0 on success, 1 on failure
    - Retention: if BACKUP_RETENTION_DAYS is set (default 7), removes backups older than N days from BACKUP_DIR
    - Handles errors gracefully (logs and exits non-zero, does not throw)

    Key implementation details:
    - Parse DATABASE_URL with `new URL()` to extract components:
      ```js
      const url = new URL(process.env.DATABASE_URL);
      const user = url.username;
      const password = url.password;
      const host = url.hostname;
      const port = url.port || "5432";
      const db = url.pathname.slice(1);
      ```
    - Use `execFileSync` (not `execSync`) to avoid shell injection from DATABASE_URL:
      ```js
      import { execFileSync } from "child_process";
      execFileSync("pg_dump", [
        `--dbname=${process.env.DATABASE_URL}`,
        "--no-owner", "--clean", "--if-exists",
        "--no-privileges", "--format=custom", "--compress=9",
        `--file=${outputPath}`,
      ], { stdio: "inherit", timeout: 300_000 });
      ```
    - Use `--dbname=connection_string` directly (safest for URL-encoded passwords)
    - Retention: use `readdirSync` + `unlinkSync` on files matching `bcm-*.dump` older than N days
    - The script is a migration sibling (same pattern as migrate.mjs and seed.mjs)

    The script should support dry-run mode:
    ```js
    if (process.argv.includes("--dry-run")) {
      console.log("[backup] DRY RUN — would execute: pg_dump ...");
      process.exit(0);
    }
    ```

    Run the script once to verify it works against a running PostgreSQL instance:
    ```
    DATABASE_URL=postgres://bcm:change-me@localhost:5432/bcm node scripts/backup.mjs --dry-run
    ```
    (dry-run only — no actual backup)
  </action>
  <verify>

  </verify>

    - Dry-run mode outputs the expected pg_dump command without executing

  </done>

<task type="auto">
  <name>Task 2: Add backup infrastructure to docker-compose files</name>
  <files>docker-compose.yml, docker-compose.yaml</files>
  <action>
    Update both `docker-compose.yml` (local dev) and `docker-compose.yaml` (Coolify variant):

    For `docker-compose.yml`:
    Add a `backup` service:
    ```yaml
    backup:
      image: postgres:17-alpine
      environment:
        DATABASE_URL: postgres://bcm:${POSTGRES_PASSWORD:-change-me}@db:5432/bcm
        BACKUP_DIR: /backups
        BACKUP_RETENTION_DAYS: 7
      volumes:
        - bcm_postgres_backups:/backups
        - ./scripts/backup.mjs:/usr/local/bin/backup.mjs:ro
      command: >
        sh -c "
          apk add --no-cache nodejs &&
          echo '0 3 * * * node /usr/local/bin/backup.mjs >> /var/log/backup.log 2>&1' | crontab - &&
          crond -f -l 2
        "
      depends_on:
        db:
          condition: service_healthy
      networks:
        - default
    ```

    Add the backup volume:
    ```yaml
    volumes:
      bcm_postgres:
      bcm_postgres_backups:
    ```

    For `docker-compose.yaml`:
    Same backup service but using the `internal` network instead of `default`:
    ```yaml
    backup:
      image: postgres:17-alpine
      environment:
        DATABASE_URL: postgres://bcm:${POSTGRES_PASSWORD:-change-me}@db:5432/bcm
        BACKUP_DIR: /backups
        BACKUP_RETENTION_DAYS: 7
      volumes:
        - bcm_postgres_backups:/backups
        - ./scripts/backup.mjs:/usr/local/bin/backup.mjs:ro
      command: >
        sh -c "
          apk add --no-cache nodejs &&
          echo '0 3 * * * node /usr/local/bin/backup.mjs >> /var/log/backup.log 2>&1' | crontab - &&
          crond -f -l 2
        "
      depends_on:
        db:
          condition: service_healthy
      networks:
        - internal
    volumes:
      bcm_postgres_backups:
    ```

    Alternative approach if the cron-based service seems heavy:
    Use a `run-once` backup command that can be triggered manually:
    ```bash
    docker compose exec db pg_dump --dbname=postgres://bcm:password@localhost:5432/bcm --no-owner --clean --if-exists --no-privileges --format=custom --compress=9 -f /backups/bcm-$(date +%Y-%m-%d-%H%M%S).dump
    ```

    Document both approaches in the script's header comment:
    - Automated: docker-compose backup service runs daily at 3 AM via cron
    - Manual: one-liner pg_dump command for ad-hoc backups
    - Schedule via Coolify: Coolify can run `node scripts/backup.mjs` as a scheduled task with DATABASE_URL env var

    The primary approach is the cron-based docker-compose service for both local and Coolify deployments.
    Keep the existing volume `bcm_postgres:` unchanged; add `bcm_postgres_backups:`.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Information Disclosure | Backup files | high | mitigate | Backup files contain all database data. The backup volume `bcm_postgres_backups` is an internal Docker volume — not exposed to host or network. In production, configure Coolify to sync volume to S3-compatible storage. |
| T-04-07 | Elevation of Privilege | backup.mjs | medium | mitigate | Script runs as node inside postgres:17-alpine container. Uses DATABASE_URL with read-only dump; no write risk. execFileSync with explicit args prevents injection. |
| T-04-08 | Repudiation | Backup cron | low | accept | Backup logs to stdout; docker compose logs backup shows timestamps. Accept minimal audit trail. |
| T-04-SC | Tampering | postgres:17-alpine image | high | mitigate | Official Docker image from Docker Hub. Pinned to 17-alpine tag (not latest). |
</threat_model>
