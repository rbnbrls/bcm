<task type="auto">
  <name>Task 1: Add npm and Playwright caching, parallelize lint job</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Rewrite `.github/workflows/ci.yml` to:

    1. **Add better dependency caching:**
       - Use `actions/cache@v4` for npm's global cache (`~/.npm`):
         ```yaml
         - name: Cache npm
           uses: actions/cache@v4
           with:
             path: ~/.npm
             key: npm-${{ runner.os }}-${{ hashFiles('package-lock.json') }}
             restore-keys: |
               npm-${{ runner.os }}-
         ```
       - The existing `actions/setup-node` with `cache: 'npm'` already caches `node_modules/` — keep it.
       - Add explicit Playwright browser caching:
         ```yaml
         - name: Cache Playwright browsers
           id: cache-playwright
           uses: actions/cache@v4
           with:
             path: ~/.cache/ms-playwright
             key: playwright-${{ runner.os }}-${{ hashFiles('package-lock.json') }}
             restore-keys: |
               playwright-${{ runner.os }}-
         ```
       - Make `npx playwright install` conditional on cache miss:
         ```yaml
         - if: steps.cache-playwright.outputs.cache-hit != 'true'
           run: npx playwright install --with-deps chromium
         ```

    2. **Restructure jobs for parallelism:**
       Current: `test` → `e2e-test` (sequential, e2e needs test)
       New: 
       - `lint` job (parallel with `test`)
       - `test` job (independent)
       - `e2e-test` job (needs `test` only)

       Wait — e2e-test currently depends on `needs: test`. But it should still run after test because if tests fail, e2e likely also fails. Move to `needs: [test]` (already there).

       Actually, the bigger optimization is: make `test` and `e2e-test` run in parallel. The test job runs Vitest unit tests, e2e-test runs Playwright. These are independent concerns. If `test` fails, we still want e2e results.

       Structure:
       ```yaml
       jobs:
         lint:
           runs-on: ubuntu-latest
           steps:
             - uses: actions/checkout@v4
             - uses: actions/setup-node@v4
               with:
                 node-version: 20
                 cache: 'npm'
             - name: Cache npm
               uses: actions/cache@v4
               with:
                 path: ~/.npm
                 key: npm-lint-${{ runner.os }}-${{ hashFiles('package-lock.json') }}
                 restore-keys: |
                   npm-lint-${{ runner.os }}-
             - run: npm ci
             - run: npm run lint

         test:
           runs-on: ubuntu-latest
           strategy:
             matrix:
               node-version: [20]
           steps:
             - uses: actions/checkout@v4
             - uses: actions/setup-node@v4
               with:
                 node-version: ${{ matrix.node-version }}
                 cache: 'npm'
             - name: Cache npm
               uses: actions/cache@v4
               with:
                 path: ~/.npm
                 key: npm-test-${{ runner.os }}-${{ matrix.node-version }}-${{ hashFiles('package-lock.json') }}
                 restore-keys: |
                   npm-test-${{ runner.os }}-${{ matrix.node-version }}-
             - run: npm ci
             - run: npm test
             - name: Upload test results on failure
               if: failure()
               uses: actions/upload-artifact@v4
               with:
                 name: test-results-${{ matrix.node-version }}
                 path: |
                   test-results/
                   !test-results/**/.gitkeep

         e2e-test:
           needs: test
           runs-on: ubuntu-latest
           timeout-minutes: 15
           steps:
             - uses: actions/checkout@v4
             - uses: actions/setup-node@v4
               with:
                 node-version: 20
                 cache: 'npm'
             - name: Cache npm
               uses: actions/cache@v4
               with:
                 path: ~/.npm
                 key: npm-e2e-${{ runner.os }}-${{ hashFiles('package-lock.json') }}
                 restore-keys: |
                   npm-e2e-${{ runner.os }}-
             - run: npm ci
             - name: Cache Playwright browsers
               id: cache-playwright
               uses: actions/cache@v4
               with:
                 path: ~/.cache/ms-playwright
                 key: playwright-${{ runner.os }}-${{ hashFiles('package-lock.json') }}
                 restore-keys: |
                   playwright-${{ runner.os }}-
             - if: steps.cache-playwright.outputs.cache-hit != 'true'
               run: npx playwright install --with-deps chromium
             - run: npm run test:e2e
             - name: Upload playwright report on failure
               if: failure()
               uses: actions/upload-artifact@v4
               with:
                 name: playwright-report
                 path: |
                   playwright-report/
                   test-results/
       ```

    3. **Remove the node-version matrix from jobs that don't need it:**
       - The `test` job has `matrix.node-version: [20]` — a single-version matrix adds unnecessary nesting. Either remove the matrix and hardcode `node-version: 20`, or keep it for future multi-version support.
       - Decision: Keep the matrix on `test` (it's already there and costs nothing extra for a single version).
       - Remove matrix from `e2e-test` (unnecessary — one version only).

    4. **Add workflow-level job summary:**
       After all jobs complete, add a summary step:
       ```yaml
       - name: Job summary
         run: |
           echo "### CI Pipeline Summary" >> $GITHUB_STEP_SUMMARY
           echo "- **Lint:** ${{ job.status }}" >> $GITHUB_STEP_SUMMARY
           echo "- **Test:** ${{ job.status }}" >> $GITHUB_STEP_SUMMARY
       ```
       Note: This runs in each job independently. For a cross-job summary, use the workflow_run trigger. Skip this for now — the GitHub UI already shows job status clearly.

    5. **Preserve existing features:**
       - `concurrency` group with cancel-in-progress
       - Trigger on push to main and PRs to main
       - `actions/upload-artifact@v4` on failure
    </action>
