    ```typescript
    import Link from "next/link";
    import type { DashboardCategory } from "@/lib/dashboard-categories";
    ```
    Accept `category: DashboardCategory` prop. Render:
    - `<article className="category-card">`
    - Icon area: `<div className="category-card-icon">{category.icon}</div>`
    - Title: `<h3 className="category-card-title">{category.title}</h3>`
    - Subtitle: `<p className="category-card-subtitle">{category.subtitle}</p>`
    - Actions list: `<div className="category-card-actions">`
      - Map over `category.actions`. The **first** action link gets `className="category-card-action primary-link"` (this is the full-card click target via ::after overlay). Remaining action links get `className="category-card-action"`.
      - Each action link: `<Link href={action.href} className="...">` with the label and a `<span className="category-card-action-desc">{action.description}</span>` if description exists.
    
    **Full-card click-to-primary implementation (per D-XX, user decision):**
    The first action link uses the CSS `::after` pseudo-element overlay technique so clicking anywhere on the card body navigates to the primary action. This avoids both invalid nested `<a>` elements and JavaScript-based navigation:
    - First `<Link>` receives `className="category-card-action primary-link"` 
    - CSS `.category-card-action.primary-link::after` creates a full-inset pseudo-element overlay
    - Other action links get `position: relative; z-index: 1` to sit above the overlay
    - No `"use client"` directive needed — pure CSS behavior
