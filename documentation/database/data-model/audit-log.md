# Schema

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `text` | `PRIMARY KEY` | Audit entry identifier (text, not UUID — generated by application). |
| `change_request_id` | `uuid` | `NOT NULL, REFERENCES change_requests(id) ON DELETE CASCADE` | The change request being audited. |
| `action` | `text` | `NOT NULL` | Type of action performed. |
| `actor` | `text` | `NOT NULL` | Who performed the action. |
| `previous_status` | `text` | | Status before the action. |
| `new_status` | `text` | `NOT NULL` | Status after the action. |
| `diff_snapshot` | `jsonb` | | JSON diff snapshot capturing state changes. |
| `client_config_version` | `text` | | Client config version at the time of the action. |
| `created_at` | `timestamptz` | `NOT NULL, DEFAULT now()` | Record creation timestamp. |

# Constraints

- `chk_al_action` — Action must be one of: `requested`, `status_change`, `approved`, `rejected`.

# Relationships

- Many-to-one with [change_requests](change-requests.md) via `change_request_id` (cascading delete)

# Indexes

| Index | Columns | Purpose |
|-------|---------|---------|
| `idx_al_change_request_id` | `change_request_id` | FK: audit entries by change request |

# Usage

Every status transition and approval/rejection action creates an audit log entry. The `diff_snapshot` captures the state changes at the time of the action, providing a point-in-time record. The `client_config_version` field links audit entries to the client configuration state at the time of the action.
