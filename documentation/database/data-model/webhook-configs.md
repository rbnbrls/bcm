# Schema

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `text` | `PRIMARY KEY` | Webhook configuration identifier (text — generated by application). |
| `name` | `text` | `NOT NULL` | Human-readable name for this webhook endpoint. |
| `url` | `text` | `NOT NULL` | Target URL for the webhook POST requests. |
| `secret` | `text` | | Optional HMAC secret for signing webhook payloads. |
| `events` | `jsonb` | `NOT NULL, DEFAULT '[]'` | Array of event types this webhook subscribes to. |
| `active` | `boolean` | `NOT NULL, DEFAULT true` | Whether this webhook is active and receiving events. |
| `created_at` | `timestamptz` | `NOT NULL, DEFAULT now()` | Record creation timestamp. |

# Usage

The `webhook_configs` table stores external endpoint configurations for real-time event notifications. When a change request transitions through its lifecycle (submitted, approved, processed, etc.), the system checks which webhooks subscribe to the relevant event type and POSTs a notification payload to the configured URL.

The `secret` field is used for HMAC-SHA256 signature generation, allowing the receiving endpoint to verify that the webhook originated from the BCM system.
